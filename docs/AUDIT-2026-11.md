# Design audit and interventions, November 2026

> Historical document: it describes the state at 0.4.0. The tools cited as "to do" (including `map_watch`, later merged into `map_refresh`) were revised in later versions; the CHANGELOG is authoritative.

This document records the audit of the MCP server's tools, the interventions that followed (version 0.4.0, branch `claude/hopeful-heisenberg-e05tkn`) and the recommended next steps. The CHANGELOG lists only the changes visible to clients; here the reasons are given too.

## 1. Starting point

36 tools, about 11,300 tokens of definitions (name, description, JSON schema) loaded in every session. Half of the tools embodied the project's thesis (cross-checked sources, explicit states, caveats in the results); the other half was a REST gateway to OpenAlex, Semantic Scholar, Google Books and ORCID, with native JSON and no judgement. The two layers shared the file but not the output contract.

Defects found by the audit, in order of weight:

1. Two products in one repository (verifier and gateway), with the context cost paid by every session.
2. A 3300-line file with 147 functions; the wheel included only `server.py` while `maps.py` and `knowledge.py` were imported at runtime: broken installed package.
3. The deployment (machine name, absolute paths) appeared in docstrings read by the model, in the README and in the HTML page.
4. The matching quality of `find_doi` (threshold 0.88, four-word rule) was not measured: only single cases in the tests.
5. Double error contract: some tools returned `{"status": "error"}`, others raised `ValueError`, which came out as a protocol error.
6. README written like a changelog (consultation dates, "the old tools remain unchanged").
7. Tools with an `action` parameter that completely changed the behaviour (openalex_query, semantic_scholar with 18 actions), sibling tools that should be merged (autocomplete, recommendations, map_watch, map_check_retractions), parameters with finite values typed as `str`.

## 2. Interventions made

### Tool surface

| Before | After |
|---|---|
| `openalex_query` with six `action`s | `openalex_query` (execution only, OQL or OQO) and `openalex_query_inspect` (translate, validate, context, properties, spec; free) |
| `openalex_autocomplete` | `openalex_entity(entity, autocomplete=...)` |
| `semantic_scholar` (18 actions) + `semantic_scholar_recommendations` | `semantic_scholar` (16 actions: Academic Graph and Recommendations) + `semantic_scholar_datasets` (4 actions) |
| `map_watch` | `map_refresh(map, new_citing=True)` |
| `map_check_retractions` | `check_retractions(map=...)` |
| link to the maps page in five descriptions | in the server instructions and in `map_list` |
| `citation_graph` with a 684-token description | pointer to `map_get` for the formats; advice on persistent maps |
| `states`, `modes`, `scope` as `str` | `Literal` |

The gateway layer (`openalex_*`, `semantic_scholar*`, `google_books`, `orcid`) is registered only with `ENABLE_GATEWAY=true`. Context cost measured by `list_tools`:

| configuration | tools | tokens |
|---|---|---|
| before the audit | 36 | ~11,300 |
| verification layer only (default) | 24 | ~6,100 |
| with gateway | 35 | ~10,300 |

### Error contract

A single decorator (`_tool`) registers the tools and converts the validation `ValueError`s into `{"status": "invalid_input", "detail": ...}`, with the parameter and the allowed values in the detail. The undecorated Python function stays accessible, so the tests that call it directly keep using `pytest.raises`. Read defaults: `per_page=25` on the lists of `openalex_entity`, `limit=20` on the list actions of `semantic_scholar`.

### Reference set for find_doi

`tests/fixtures/find_doi_cases.json`: 39 cases with pre-built candidates per source and synthetic DOIs (`10.5555/...`), not real identifiers. `tests/test_find_doi_reference_set.py` runs `find_doi` with simulated sources and measures precision and recall over the whole set; the thresholds are 1.00 and 0.85. Three cases marked `known_gap` (truncated title, transliterated surname, prepended subtitle) are known gaps in the current rules and weigh on recall on purpose. Current state: precision 1.00, recall 0.90.

Declared limit: the candidates are built by hand, not responses recorded from the APIs, so the set verifies the acceptance and ordering rules, not the sources' parsers.

### New features

- `check_citations(text, references)`: cross-check, without network, between APA author-date citations and the bibliography. It reports citations without an entry, uncited entries, discordant years for the same first author, ambiguous entries (same author and year without a suffix). It matches only the first author's surname and the year: a match is not a verification, which stays with `find_doi` and `verify_doi`.
- `dnb` among the databases of `search_literature`: the Deutsche Nationalbibliothek's SRU, monographs and translations in German, without abstracts, year filter applied client-side. PhilArchive was not integrated: it exposes only OAI-PMH, which allows harvesting by date and set but not searching.

### Project hygiene

- Wheel: includes `maps.py` and `knowledge.py`; a test verifies it against the imports of `server.py`.
- No reference to the deployment machine in code, descriptions and page; `ENABLE_GATEWAY`, `KNOWLEDGE_DIR` and `STATE_DIRECTORY` documented; the systemd drop-in in the README is an example.
- `CHANGELOG.md` separate from the README; version 0.4.0 because the renames break clients.
- `tests/test_tool_surface.py` fixes the conventions: descriptions under 1800 characters, enumerations for parameters with finite values, the gateway list, `invalid_input` through `call_tool`, no name defined twice at module level.
- Descriptions of `search_literature` and `openalex_account_write` shortened.

### Pre-existing bugs found by the new tests

1. With `is_book=True`, `edition_mismatch` appeared only if the year differed by one; with two or more years the candidate was discarded earlier and the status was `no_confident_match`, contrary to what the description promised. Now a book's year decides the edition, not the match.
2. A second `_expand` function (map expansion) shadowed the first (boolean query syntax): Europe PMC, DOAJ, HAL and Zenodo failed at runtime with a `TypeError` ever since the maps existed. The tests did not see it because they simulate the downstream adapters. Renamed to `_expand_terms`.
3. The CQL query for the DNB lacked the explicit conjunction between adjacent terms (CQL has no implicit AND): `_cql` inserts it, leaving `NOT` binary.

State of the suite: 422 green tests, 3 declared xfail, without network.

## 3. What remains to do by hand after the merge

1. On the server: update the code, add `ENABLE_GATEWAY=true` to the systemd drop-in if you want the OpenAlex, Semantic Scholar, Google Books and ORCID pass-throughs, restart the service.
2. In the clients (Claude web): disable and re-enable the connector so that it re-reads the tool names.
3. The *Literature maps* page must be republished at the same link from the updated source: it calls `map_refresh` with `new_citing` instead of `map_watch`.

## 4. To verify in use

- If the client does not show the server instructions to the model, after `map_create` the link to the page no longer appears: in that case put it back in the description of `map_create` only.
- `check_citations` is a regular-expression heuristic tried on a constructed text. Pass it a real article with its bibliography and look at the false positives: names with compound particles ("de la Torre"), compound surnames without a hyphen, capitalised words followed by a year in brackets ("Proceedings (2019)").
- The DNB adapter was not run against the real service: a call with `database="dnb"` is the missing check.
- `find_doi` accepts the candidate if the given surname appears among any authors, not only as the first (case `first_author_given_as_second` in the set). It is useful when whoever cites gets the order wrong, but `first_author` is not really "first author". If you prefer the strict check: one line in `_author_ok` and the set's case to flip; otherwise rename the parameter to `author` in a later version.

## 5. Recommended next steps, in order

1. **Close the reference set's gaps** one at a time, raising the recall threshold at each closure: prefix similarity for truncated titles, normalisation of common transliterations for surnames, comparison with subtitle and title swapped.
2. **Record real API responses** for about ten cases of the set, so that the sources' parsers are covered too; keep them as JSON fixtures.
3. **Split `server.py`** into a package (`http`, `matching`, `sources/`, `search/`, `maps`, `gateway/`, `prompts`), without changing the tool names: pure refactoring, in a commit separate from any functional change.
4. **Make the error output uniform**: bring the existing `{"status": "error"}` dictionaries to the format of `invalid_input` (parameter, allowed values, what to do).
5. **Extend `check_citations`** to numeric styles and to citations with multiple pages only if use requires it; first measure its precision and recall on three real articles, as for `find_doi`.
6. **Do not invest further in the gateway**: the API coverage is complete and the marginal return is low; every tool added there costs all the sessions that enable it.
